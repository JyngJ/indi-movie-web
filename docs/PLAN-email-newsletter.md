# 상영 알림 이메일 발송

2026-10-19 구현안. 뉴스레터·이야기 접수·리뷰는 제외한다.

> “팝업 띄워주고, 안하겠다고 하면 그냥 안하도록 두자.”
>
> “발송 주기는 일단 주 2회 정도로 하자. 월, 금 아침으로”
>
> “3회 말고 일단 쭉 진행하고 사용하는 사람 많아지면 일괄로 한번에 하자. 일단 저장만 해둬. 코멘트 적어두고”

## 반영한 동작

- 로그인한 회원에게 수신 이메일 등록 팝업을 표시한다. 기존 로그인 방식은 유지한다.
- ‘지금은 받지 않기’ 또는 Escape로 닫으면 자동으로 다시 묻지 않는다. 서버와 기기에 거절을 기록한다.
- 나중에 MY → 알림 설정에서 등록·주소 변경·해지할 수 있다.
- 주소를 직접 입력하고 선택 동의 후 인증 메일을 받는다. 링크를 열어 인증 버튼을 눌러야 구독이 활성화된다.
- 관심 영화·감독·극장의 새 상영·막바지 소식을 월·금 한국 시간 오전 9시에 요약한다. 새 소식이 없으면 보내지 않는다.
- 기존 종류별 알림 설정을 따르며, 이메일 수신 해지와 소식 탭은 분리한다.
- 발송 시점의 관심 목록·지역·실제 예정된 회차·막바지 판정을 다시 확인한다.
- 구독 이후 생성된 소식만 대상으로 한다. 이미 메일로 보낸 이벤트는 제외하고, 같은 영화의 이벤트는 한 항목으로 묶는다.
- 빈도 설문 자동 발송은 보류한다. 이용자가 충분히 모이면 일괄 설문한다. 의견 화면·저장 기능은 유지하고, `shouldAskFrequency`에 재개 조건을 정해야 한다는 TODO를 남긴다. 현재는 3번째를 포함한 모든 메일에 설문 링크를 넣지 않는다.
- 인증·의견·해지는 영화볼지도 `/email/manage`에서 처리한다. 링크를 여는 GET 요청만으로 상태를 바꾸지 않는다.
- 메일 하단 해지 링크는 로그인 없이 사용할 수 있다.

## 발송·운영

발신 주소: `indi.movie.map@gmail.com`. Gmail API 발송 어댑터를 사용한다.

주소 인증·구독·발송 이력은 기존 카카오 알림과 별도 테이블에 보관한다. 정기 작업의 동일 슬롯 중복 실행을 막고, 전송이 거절된 작업만 안전하게 재시도한다. 전송 요청 후 응답이 없거나 성공 기록에 실패하면 `unknown`으로 남겨 수동 확인 전 재발송하지 않는다. 상세 설정은 `RUNBOOK-email-notifications.md`를 따른다.

## 아직 운영에 연결할 작업

- 새 SQL을 운영 DB에 적용
- 발신 Gmail의 OAuth 발송 권한 연결
- 웹 서비스 환경 변수와 예약 발송 작업의 비밀 값 설정
- 내부 주소의 인증·메일 수신·해지 실측 후 기능 켜기

주 2회 메일 사이에 끝나는 회차는 안내하지 못할 수 있다. 예약 실행 서비스의 지연 때문에 정확히 09:00 도착을 보장하지 않는다.

## 화면 검토 반영 (2026-10-19)

- 알림 설정에서는 기존 새 상영·막바지 상영과 같은 목록 행으로 수신 주소·상태와 등록하기/편집하기만 보여준다.
- `/my/notifications/email` 하위 페이지에서 주소 등록·변경·재인증·해지를 처리한다. PC MY 팝오버에서도 편집을 누르면 해당 페이지로 이동한다.
- 동의 체크박스는 문장이 여러 줄이어도 첫 줄의 가운데에 맞춘다.
- 메일의 인증·해지·빈도 의견 링크는 화면 가운데 카드로 열린다. 빈도 의견은 두 선택을 그대로 적은 버튼으로 제출한다.

레퍼런스에서 확인한 문구:

> “Change” — GOV.UK Summary list의 행별 편집 동작
>
> “Manage emails” — Notion 계정 설정의 이메일 관리 진입

목록은 현재 값과 편집 입구만 표시하고 수정은 별도 화면에서 수행하는 구조를 참고했다.

- https://www.notion.com/help/account-settings

## 디자인 시스템 재점검 (2026-10-19)

기준: `src/styles/tokens.css`, `src/design-system/guides.ts`, `interactionRules.ts`, `writing.ts`. Figma 동기화 작업이 아닌 코드 디자인 시스템과의 대조다.

확인한 규칙:

> “카드 안 요소 간격은 spacing/3(12)”
>
> “방금 한 행동의 결과는 토스트”

- 카드 내부 여백·간격은 12px, 페이지 거터는 `--gutter`(16px), 팝업 여백은 `--gutter-sheet`(24px)로 맞췄다.
- 체크박스 선택색도 `--color-primary-base`를 사용한다. 문장이 여러 줄이어도 첫 줄 가운데를 유지한다.
- 이메일 형식 오류는 공용 Input의 error·aria-invalid로 표시한다. 브라우저 기본 오류 풍선 대신 한국어로 다음 행동을 안내한다.
- 인증 메일 발송 결과를 본문과 토스트에 중복 표시하지 않는다. 인증 대기 안내는 현재 상태로 남긴다.
- 등록·해지 각각 누른 버튼에 로딩 표시를 띄우고 처리 중 중복 클릭을 막는다.
- 한 문장 마침표·로딩 문구를 정리하고 알림 설정 저장 오류에 내부 예외를 노출하지 않는다.
- 브라우저 검사에 PC·모바일 카드의 실측 여백·간격과 입력 오류 확인을 추가했다.

## 여백·동등한 빈도 선택 보완 (2026-10-19)

- 메뉴 목록은 이메일 행 전체를 누르는 MenuRow와 꺾쇠로 하위 페이지 이동을 표시한다.
- 폼 안내와 지난 상영 안내를 입력 위에 모으고, 입력 레이블은 ‘수신할 메일 주소’로 통일한다. 동의 문구는 ‘(선택)’ 뒤에서 줄을 나눈다.
- 독립 폼의 페이지·카드 여백은 24px, PC 카드 여백은 32px, 구역 사이는 24px로 넓힌다. 기존 메뉴의 16/12/8 거터와 구분한다.
- 인증·해지 카드의 로고는 144×48에서 72×24로 줄인다. 링크의 최소 클릭 높이 44px는 유지하고 글자를 세로 가운데에 놓는다. 기존 하단 빈 공간은 별도 마진이 아니라 링크 44px 안의 글자 줄 18px와 카드 패딩 12px에서 생겼다.
- 빈도 의견은 ‘더 자주 / 지금 정도 / 더 가끔’을 같은 톤으로 나란히 표시한다. 숫자별 실제 빈도를 정의하지 않은 5단계 슬라이더는 도입하지 않는다.
- 중립 의견은 `same`으로 저장한다. 발송 주기를 즉시 바꾸지 않는 기존 정책은 유지한다.

감사 수치 설명: 빈도 응답 3개를 공용 Button의 배열 렌더링으로 바꾸고, 이메일 설정의 ListRow+Button을 MenuRow 하나로 합쳤다. 정규식 감사는 반복 렌더링을 하나로 세므로 실제 공용 컴포넌트 사용은 유지되지만 채택률은 87.0%에서 86.9%로 바뀐다. 이 구성 변경을 근거로 기준선을 조정하며, 관계없는 화면을 고쳐 수치를 맞추지 않는다.


## 로그인 화면의 이메일 소개 (2026-10-19)

- 로그인 위에 정적 메일 예시 카드를 둔다. 예시임을 표시하고 허구의 영화·회차·개인 정보는 넣지 않는다.
- 카카오와 Google 로그인 버튼을 같은 높이·폭으로 제공한다. 수신 동의는 로그인 이후 별도 선택이다.
- 현재 공개 Auth 설정의 `external.google`은 false다. 버튼은 기존 Google OAuth 경로에 연결했으며, 비활성 상태에서 누르면 로그인 화면에서 카카오를 안내한다. 실제 사용 전 Google Client ID·Secret과 콜백 URL을 인증 제공자에 설정해야 한다.
- Google 로고는 공식 브랜드 가이드의 허용된 로그인 버튼 용도로만 사용한다. 출처: https://developers.google.com/identity/branding-guidelines · 원본: https://developers.google.com/static/identity/images/g-logo.png
- 공용 Card·GoogleLoginButton 채택으로 UI 감사 채택률이 87.0%로 올라 기준선을 함께 반영했다.


## 로그인 예시 메일 도착 모션 (2026-10-19)

- 비로그인 이메일 설정 화면도 스크롤 본문 높이를 채워 세로 가운데에 로그인 영역을 둔다. 짧은 화면에서는 본문이 스크롤된다.
- 카드 자리를 확보한 뒤 0.6초 대기, 0.2초 동안 opacity·translateY(16→0)·scale(0.94→1.02→1)로 한 번만 등장한다. 버튼·설명은 움직이지 않는다.
- reduced motion에서는 지연·이동 없이 바로 표시한다. 예시 표시를 유지하고 실제 메일이 도착했다는 알림이나 소리는 만들지 않는다.
- 참고: https://motion.dev/examples/js-notifications-stack · https://emilkowal.ski/ui/building-a-toast-component


### 도착 연출 강화

사용자 요청에 따라 단순 팝을 약 1.3초의 소개 연출로 바꿨다. 0.2초부터 봉투가 등장하고, 0.45초에 덮개가 열리며, 0.65초부터 카드가 튀어나와 좌우로 뒤뚱거리며 정착한다. 반짝이 4개가 짧게 퍼지고 사라진다. 레이아웃·버튼 위치는 고정하며 reduced motion에서는 봉투·반짝이를 렌더링하지 않고 카드만 즉시 보인다. 참고: https://lottiefiles.com/free-animation/new-mail-mFjgGGe9Ch · https://codepen.io/nitishkmrk/pen/qqNXPK · https://motion.dev/examples/react-confetti


최종 조정: 봉투·반짝이는 제거한다. 0.4초 대기 후 카드의 팝·뒤뚱 효과만 0.55초간 한 번 재생한다.


### 이메일 등록 화면 조정

이메일 입력 카드도 스크롤 본문 가운데에 둔다. 주소가 비었거나 normalizeEmail 검증에 실패하거나 동의하지 않으면 CTA를 비활성화한다. 신규 등록에는 “지금은 괜찮아요” 버튼을 제공하며 거절 상태를 기억하고 알림 설정으로 돌아간다. 이미 수신 중인 계정의 해지 동작은 유지한다.


### 구글 이메일 기본값·입력 지우기

저장한 수신 주소가 있으면 우선 사용하고, 없으면 Google 계정의 이메일을 기본값으로 표시한다. 동의는 기본 해제다. 사용자가 입력하거나 지운 뒤에는 기본값을 다시 덮어쓰지 않는다. 내용이 있을 때 44px 탭 영역의 지우기 버튼을 표시하고, 지운 뒤 입력 초점을 유지한다. CTA·보조 버튼 간격은 12px, 팝업 하단 여백은 모바일 16px·PC 24px로 줄였다.
